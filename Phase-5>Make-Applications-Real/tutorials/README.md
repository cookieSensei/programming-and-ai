# Phase 5 — Very Detailed Tutorials

## Make Applications Real

These tutorials are expanded from the Phase 5 curriculum and its six reference projects.

Phase 5 is explicitly structured around:

```text
Database
   ↓
SQL
   ↓
Users & Authentication
   ↓
Production Configuration
   ↓
Deployment
   ↓
Minimum Working Product
```

The reference implementation describes Phase 5 as the stage where a Phase 4 web application gains the pieces needed to become a Minimum Working Product. The goal is not to make students production engineers; it is to build the simplest working version of an idea that another person can actually use.

## Teaching philosophy

These are deliberately much more detailed than the short project markdowns.

They are designed to help a beginner understand:

- the mental model behind each project
- why the technology is being introduced
- how the pieces connect
- what to test
- what commonly goes wrong
- how to use ChatGPT without surrendering understanding
- how each technical feature contributes to the MWP

The student does **not** need to become a database administrator, authentication specialist, DevOps engineer, or professional software architect.

The intended outcome is independent product-building confidence.

## Recommended use

Use the project implementations as working references.

Read the relevant tutorial before or during the corresponding project.

For the final MWP project, return to earlier tutorials whenever the product needs:

- database design
- SQL inspection
- authentication
- authorization
- environment configuration
- deployment
- debugging
- scope control

## Phase 5 completion

A successful Phase 5 outcome is not "I know every technology."

It is:

> I can take a small idea, make the core flow work, persist the information it needs, configure it for production, put it online, let another person use it, and learn from what happens.
